sotto

Open 2400 bit/s digital voice for FM radios: a vocoder, error correction and a C4FM modem path, built for small fixed-point DSPs.

New to vocoders? How sotto works is a short illustrated course (written for high-school students) on pitch, envelopes, quantization, synthesis and the radio link.

Part 1: sotto's encoder against Codec 2's

Both encoders run at 2400 bit/s (48 bits every 20 ms). Each pair went through exactly the same chain: the same System Fusion (C4FM) frames and error protection, the same simulated radio channel with the same fading, and the same software receiver. The only difference is the encoder and decoder.

no radio channel UHF 446 MHz, 60 km/h, 52 dB-Hz (a weak mobile signal) VHF 146 MHz, 30 km/h, 56 dB-Hz (slow fading)

The score is PESQ, an automatic speech-quality estimate from 1 (bad) to 4.5 (excellent), averaged over three fading runs. sotto v3 is an early prototype: a mel-spaced spectral envelope in place of Codec 2's 10th-order LPC, quantized with a codebook trained on 600 speakers, and a tracker that decides pitch and voicing together, with Codec 2's synthesis.

What you're hearing

sotto v3 (Part 1) describes the spectrum with 20 mel-spaced amplitudes, quantized with 34 bits by a three-stage codebook trained on 600 volunteer speakers from Google's Speech Commands recordings, plus a formant postfilter and a frame-energy field, where Codec 2 uses a 10th-order LPC filter. Its tracker starts from Codec 2's pitch estimate and fixes octave errors (pitch reported at double or half its true value), which Codec 2 makes most often on higher voices. The same tracker decides which frames are voiced, follows pitch up to 500 Hz, and avoids the warbling that wandering pitch causes in quiet transitions. Pauses decode as true silence. It keeps Codec 2's synthesis. It needs no memory between frames, so a lost frame doesn't damage the next one.

VW slot (used for everything in Part 1) puts the voice in the full-rate part of the Fusion frame, adds a CRC to each 20 ms frame and protects everything with a strong tail-biting convolutional code. DN slot + our code uses the half-rate slot Fusion radios use for DN mode, with a weaker version of the same code. Fusion-style protection mimics how DN protects its voice bits (the first 27 bits sent three times, the rest unprotected), applied to Codec 2. That's a statement about Codec 2 with that protection, not about AMBE+2, whose decoder is built around it.

At 146 MHz and 30 km/h, fades outlast the 100 ms interleaver, so whole frames are lost; longer interleaving and better concealment are on the list.
